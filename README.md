## 📖 About the Challenge

**The GitHub 7-Day Challenge** is a structured learning program that guides you through the essentials of GitHub and Git in just one week. Unlike static PDFs or lengthy tutorials that never stick, this challenge combines:

- **Bite-sized daily lessons** – One focused concept per day
- **Hands-on tasks** – Apply what you learn directly on your GitHub account
- **Accountability checkpoints** – Mark progress and stay on track
- **Community support** – Join other beginners hitting the same milestones
- **Real portfolio results** – Walk away with a live, browsable, job-application-ready GitHub profile

### Why This Challenge?

Reading about `git commit` and actually running `git commit` on your own repo are two different skills. Only one of them shows up on your GitHub profile. This challenge fixes that with small daily reps, not a 40-page manual you skim once and never revisit.

## 📅 Challenge Structure

This is a **7-day, guided challenge** with one checkpoint per day. Each day unlocks at a scheduled time and includes:

1. **A focused lesson** (5–10 minutes)
2. **A hands-on task** (20–40 minutes)
3. **A checkpoint** to mark completion
4. **Optional resources** for deeper learning

### Daily Time Commitment

- **Day 1–7**: 30–60 minutes per day
- **Total**: ~4–5 hours over one week
- Flexible timing – complete tasks at your own pace within each day

## 📆 Day-by-Day Breakdown

### **Day 1: Get Your Developer Home Base Set Up**
**Goal:** Create a GitHub account, configure your environment, and make your first commit.

**What You'll Do:**
- Create and configure your GitHub account
- Set up Git on your local machine
- Configure your Git identity (`git config`)
- Create your first repository
- Make your first commit
- Push to GitHub
- Verify everything works

**Key Concepts:** Authentication, local setup, first-time workflow  
**Estimated Time:** 45 minutes  
**Deliverable:** A GitHub account with one public repository

---

### **Day 2: Learn the Handful of Commands You'll Actually Use**
**Goal:** Master the 8–10 Git commands that handle 90% of your daily work.

**What You'll Do:**
- Learn `git status` – Always know what's happening
- Learn `git add` – Stage your changes
- Learn `git commit` – Create meaningful commits
- Learn `git push` – Send your work to GitHub
- Learn `git pull` – Sync with teammates
- Learn `git log` – Review your history
- Practice these commands on a test project
- Understand the staging area

**Key Concepts:** The Git workflow cycle, commit messages, staging  
**Estimated Time:** 50 minutes  
**Deliverable:** A commit history showing proper workflow

---

### **Day 3: Understand Branches and Safe Experimentation**
**Goal:** Learn how branches let you experiment without breaking main code.

**What You'll Do:**
- Understand why branches exist
- Create a new branch (`git branch`, `git checkout`)
- Make changes on your branch
- See the difference between branches
- Understand the default branch concept
- Switch between branches safely
- Practice common branch patterns

**Key Concepts:** Branch strategy, feature branches, safety  
**Estimated Time:** 40 minutes  
**Deliverable:** A repository with multiple branches showing different experiments

---

### **Day 4: Collaborate Using Pull Requests**
**Goal:** Learn the pull request workflow used in real teams.

**What You'll Do:**
- Understand what a pull request is
- Create your first pull request
- Add a meaningful description
- Review your own changes before merging
- Merge a PR on GitHub
- Delete old branches
- Understand PR etiquette and review culture

**Key Concepts:** Code review, PR conventions, collaboration  
**Estimated Time:** 45 minutes  
**Deliverable:** A completed and merged PR in your repository

---

### **Day 5: Handle Conflicts and Undo Mistakes**
**Goal:** Learn to recover from mistakes and resolve merge conflicts.

**What You'll Do:**
- Learn `git revert` – Undo a commit safely
- Learn `git reset` – Move HEAD (use carefully)
- Understand merge conflicts
- Resolve a merge conflict manually
- Practice the "break it on purpose" technique
- Learn `git stash` – Temporarily save work
- Understand when to ask for help

**Key Concepts:** Error recovery, conflict resolution, undo strategies  
**Estimated Time:** 50 minutes  
**Deliverable:** A repository showing you've recovered from (and learned from) mistakes

---

### **Day 6: Polish Your Profile and Showcase Your Work**
**Goal:** Make your GitHub profile look professional and job-application-ready.

**What You'll Do:**
- Create a profile README (the `username/username` repo)
- Write an engaging bio
- Highlight your best projects
- Pin your best repositories
- Add relevant topics/tags to repos
- Customize your profile appearance
- Review your profile from a hiring manager's perspective
- Add project descriptions and badges

**Key Concepts:** Portfolio presentation, personal branding, GitHub UX  
**Estimated Time:** 60 minutes  
**Deliverable:** A complete, professional GitHub profile

---

### **Day 7: Showcase Your Portfolio and Next Steps**
**Goal:** Finalize your portfolio and create a plan for ongoing growth.

**What You'll Do:**
- Review everything you've built
- Share your profile (get feedback)
- Plan your next projects
- Learn about GitHub features you haven't used
- Set up GitHub Pages (optional)
- Understand GitHub's advanced features
- Create an action plan for your first real projects
- Celebrate and reflect

**Key Concepts:** Continuous learning, next projects, long-term growth  
**Estimated Time:** 45 minutes  
**Deliverable:** A finalized portfolio ready for job applications

## 🔧 Prerequisites

Before starting, ensure you have:

### Required
- A **web browser** (Chrome, Firefox, Safari, or Edge)
- An **email address** (for GitHub signup)
- A **computer with Git installed** (Mac, Windows, or Linux)
- **Administrator access** to your computer (to install software if needed)

### Optional but Helpful
- Basic comfort with using a terminal/command line
- A text editor (VS Code, Sublime Text, Atom, or even Notepad)
- 30–60 minutes per day for 7 days

### How to Install Git

**macOS:**
```bash
# Using Homebrew
brew install git

# Or download from: https://git-scm.com/download/mac
```

**Windows:**
```bash
# Using Chocolatey
choco install git

# Or download from: https://git-scm.com/download/win
```

**Linux (Ubuntu/Debian):**
```bash
sudo apt-get install git
```

**Verify installation:**
```bash
git --version
```

## 🚀 Getting Started

### Step 1: Sign Up for the Challenge
Visit the challenge page and enroll:
```
https://nas.com/code-crumbs/challenges/the-github-7day-challenge-zero-to-portfolioready
```

### Step 2: Create a GitHub Account
If you don't have one already:
1. Go to [github.com](https://github.com)
2. Click **Sign up**
3. Enter your email, create a password, and choose a username
4. Verify your email
5. Complete the setup wizard

### Step 3: Configure Git Locally
```bash
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
```

### Step 4: Create Your First Repository
1. Go to [github.com/new](https://github.com/new)
2. Name it `my-first-repo`
3. Add a description
4. Choose **Public** (for your portfolio)
5. Check **Add a README file**
6. Click **Create repository**

### Step 5: Clone Your Repository Locally
```bash
git clone https://github.com/YOUR-USERNAME/my-first-repo.git
cd my-first-repo
```

### Step 6: Make Your First Commit
```bash
echo "# My First Repository" >> README.md
git add README.md
git commit -m "Initial commit: Add README"
git push origin main
```

🎉 **Congratulations!** You've completed the basic setup. Day 1 is underway!

## 💡 Tips for Success

### ✅ **Do's**
- **Start early** – Don't save tasks for the last minute of the day
- **Test everything** – Actually run the commands, don't just read them
- **Break it on purpose** – Make mistakes in a safe space to learn recovery
- **Ask questions** – Use the community forum or challenge comments
- **Review your progress** – Look at your GitHub after each day
- **Take notes** – Write down commands and concepts in your own words
- **Share your journey** – Post your progress; it helps others and feels great

### ❌ **Don'ts**
- **Don't skip the hands-on tasks** – Reading doesn't build muscle memory
- **Don't memorize** – Understand the concepts; commands come naturally over time
- **Don't rush** – Spending an extra 20 minutes to fully understand is better than moving fast
- **Don't compare timelines** – Everyone moves at their own pace; that's normal
- **Don't ignore errors** – They're the best learning opportunities
- **Don't use `sudo` for Git** – It's rarely necessary and can cause issues
- **Don't commit sensitive data** – Never push passwords, API keys, or personal info

## 🆘 Troubleshooting

### Common Issues & Solutions

#### **"Git is not installed"**
```bash
# Check if Git is installed
git --version

# If not, install it (see Prerequisites section above)
```

#### **"Permission denied" when trying to push**
- You likely need to set up SSH keys or use a personal access token
- See: https://docs.github.com/en/authentication/connecting-to-github-with-ssh

#### **"fatal: not a git repository"**
- Make sure you're in the correct directory
- Run: `pwd` to check your current location
- Run: `git init` if you need to initialize a new repo

#### **"Merge conflict! What do I do?"**
- This is normal and happens in Day 5
- Don't panic — conflicts are learning opportunities
- Follow the Day 5 lesson for resolution steps
- Reference: https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/addressing-merge-conflicts

#### **"I pushed something I shouldn't have"**
- Don't panic — version control has your back
- Learn `git revert` to undo safely (Day 5)
- For sensitive data: https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository

#### **"My commits look messy"**
- This is normal for beginners
- Day 2 teaches how to write clear commit messages
- Reference: https://chris.beams.io/posts/git-commit/

#### **"I'm behind on the challenge"**
- It's okay! There's no penalty for taking longer
- You can catch up anytime
- The goal is to learn, not to rush
- Some days might take 90 minutes; that's normal

## ❓ FAQ

**Q: Do I need to know how to code?**  
A: Nope! This challenge teaches you Git and GitHub, not programming. Day 1 tasks don't require any coding.

**Q: Can I do the challenge offline?**  
A: Most tasks yes, but you'll need internet to push to GitHub and interact with the platform.

**Q: What if I miss a day?**  
A: No problem! This isn't a race. You can pick up where you left off anytime.

**Q: Will my GitHub account be ready for a job application after Day 7?**  
A: Absolutely! You'll have a polished profile with real projects. The quality is job-application-ready.

**Q: Can I use GitHub Desktop instead of the terminal?**  
A: Yes! GitHub Desktop works great for this challenge, though learning the terminal commands will benefit you long-term.

**Q: Is this challenge still relevant in 2026?**  
A: Absolutely. Git and GitHub fundamentals haven't changed in years and aren't going anywhere.

**Q: What if I forget a command?**  
A: That's perfectly normal. We all forget. Keep a cheat sheet handy, or just search "git [command name]."
